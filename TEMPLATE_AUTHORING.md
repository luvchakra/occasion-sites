# Adding a new occasion template (e.g. Birthday, Anniversary)

There's no template-building UI on purpose — you build the site itself
however you like (or ask Claude to build one in a separate session), then
upload it as a **zip file** from the Templates page in the admin tool. It
auto-generates the admin form from your file — the only thing to get right
is the convention below.

Zip it up as:

```
index.html            the site itself, at the ROOT of the zip
images/                backdrop/decorative images that are the SAME for every customer
videos/                 same idea, for video
```

(A single wrapper folder, like `my-template/index.html`, is fine too — the
upload strips it automatically. That's exactly the shape of the original
`wedding-site-package.zip` this tool's first template came from.)

## The one required convention: `index.html`

The site must read ALL customer-specific content from one object, set near
the top of the file:

```html
<script>
window.SITE_CONFIG = {
  person: { name: "Jordan", photo: "" },
  party: { date: "", venue: "" },
  gallery: [
    { photo: "images/example1.jpg", caption: "Example" }
  ]
};
</script>
<!-- ==================== END OF CONFIGURATION ==================== -->
```

Then, in a later `<script>` block, plain JS reads `window.SITE_CONFIG` and
fills in the page (`textContent`, `src`, building repeated cards from an
array, etc.) — see `templates/wedding/index.html` for a full example: the
whole "apply config" block near the bottom of the file.

Publishing a customer's site only ever replaces the
`window.SITE_CONFIG = {...};` object with their data — your markup/CSS
below the `END OF CONFIGURATION` marker is never touched.

Photo/video fields should be referenced as plain relative paths, e.g.
`"images/main.jpg"` — the admin tool copies each customer's uploaded photos
into `images/` next to the published page.

**Leave one real example item in every array** (like `gallery` above),
not `[]`. The admin form's fields are generated by reading your default
`SITE_CONFIG` values — for an array, that means reading the shape of its
first item. An empty array has no shape to read, so that field is silently
skipped from the generated form (the upload will tell you which fields, if
any, got skipped this way).

## What gets auto-generated

Uploading builds the admin form for you: every string field becomes a text
box (or a photo-upload field, if its name contains "photo"/"image"/etc., or
a URL field for "url"/"link", or a bigger textarea for long text/"story"/
"description"-ish names), and every array becomes a repeatable "add
another" section using its first item as the template.

If a field comes out wrong (wrong type, bad label), there's no in-tool
editor for that yet — fix it in the repo directly at
`templates/<id>/template.json` (each field is
`{ key, label, type, itemFields? }`) and it takes effect immediately, no
redeploy needed.

## `images/` and `videos/`

Everything in the zip outside of `index.html` is copied into *every*
customer's published site automatically, before their own uploaded photos
are layered on top. Put here: background textures, a fixed intro video, and
any fallback images your markup references directly outside of
`SITE_CONFIG` (e.g. the built-in example event/gallery photos a page falls
back to when a customer hasn't filled something in yet).
